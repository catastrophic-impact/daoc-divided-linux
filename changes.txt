2026-11-11
- BUG FIXED, found by the owner's test: admin screen Quit -> "Stop the server too" did not stop the server. The screen called self.exit(10), but Textual's first argument is a result, not the exit code, so it always exited 0, and daoc-admin's "10 = stop" branch only waited for the server and never sent the stop. The server kept running while the screen closed; the owner then ended it another way (killed mid-shutdown, no final save; the database stayed consistent, changes after the last autosave were lost). Now Quit -> Stop does what the Stop button does (save, stop, wait) before closing. daoc-server.sh stop and the admin screen now also say so loudly when the server exited without logging "Stopped" (no final save). Regression test in tui/test_tui.py (fails without the fix). Checked on a copy: both stop routes log "Saving database... / checkpoint / Stopped", PID file removed; a server killed mid-shutdown gives the warning and exit code 1.
- Merged upstream DividedRealms a0555cd (DR-dev-0.1g, Catacombs and Crafting; 0.1b..0.1g) into branch sync-2026-11-11: build ok, 8,199 tests pass (tests only, nothing checked in game yet).
